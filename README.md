# 하루종이 (Haru-Paper)

**디지털 디톡스를 종이로.** 아침에 폰을 여는 대신, 전날 폰에서 골라 둔 콘텐츠가 정해진 시각에
작은 감열 프린터로 한 장 인쇄되어 나온다.

- 폰 웹앱에서 **포맷**(텍스트·이미지·날짜·날씨 블록을 쌓은 종이 한 장)을 만들고
- **예약**(요일별 반복, 일회성, 지금 인쇄)을 걸면
- 집에 있는 작은 보드(Orange Pi Zero 2W)가 **인터넷이 끊겨도** 그 시각에 프린터로 인쇄한다

> 상태: **서버·웹앱·Pi 에이전트가 전부 코드로 있고, Pi가 서버를 상시 폴링 중이다.**
> 계정·로그인·기기별 토큰(M6)도 구현됐다. 프린터 연결은 **BT(SPP/RFCOMM)로 확정·완료**됐다
> (V1~V3 통과, M5 실물 인쇄까지 완료 — 2026-09-17). 레이아웃/위젯 엔진(M7)은
> 스키마·편집기까지만 있고 실행 러너는 아직이다.
> 문서 색인·현재 상태는 [`docs/README.md`](docs/README.md), 최초 결정 기록은 [`docs/init_plan.md`](docs/init_plan.md).

## 구조

```
폰 웹앱(PWA) ──HTTPS── 서버(Spring Boot, Docker) ──폴링── Pi 에이전트(Python) ──BT(SPP)── 감열 프린터
                         (전 구간 Tailscale 내부망)
```

| 구성 | 디렉터리 | 하는 일 |
|---|---|---|
| 앱 | [`app/`](app/) | 로그인, 포맷 편집(드래그)·미리보기, 예약, 지금 인쇄, 이력·기기 상태 (React + TypeScript + Vite PWA) |
| 서버 | [`server/`](server/) | 계정·기기 소유권, 포맷·예약 저장, 프린터 폭에 맞춘 PNG 렌더, 날씨, Pi 동기화 API (Spring Boot 4 + Java 21 + MariaDB) |
| Pi | [`pi/`](pi/) | 서버 폴링, 예약 로컬 계산, PNG 캐시, 프린터 드라이버·전송, 결과 업로드 (Python) |

- 프린터 프로토콜을 아는 코드는 `pi/printer/<모델>`뿐이다. 서버와 앱은 "폭 N px, dpi D의 종이"만 안다
- 지원 프린터: Phomemo M832(300dpi), 110mm 연속 롤, BT SPP/RFCOMM 채널 1로 연결. 프로토콜은 선행 프로젝트
  [detox-printer](https://github.com/Justant-source/detox-printer)에서 리버싱했다

## 마일스톤

| | 내용 | 상태 |
|---|---|---|
| M0 | 저장소 뼈대, 문서 | 완료 |
| M1 | M832 드라이버 + USB/BT 전송 | 코드 있음. 실물 인쇄는 M5(BT)에서 완료 |
| M2 | 서버 | 완료 |
| M3 | 웹앱 | 완료 |
| M4 | Pi 에이전트 | 코드 있음, Pi에서 상시 구동 중 |
| M5 | Pi 실물 설치, 연결 방식 결정 | **완료.** `bt` 확정, 실물 인쇄 1회 육안 확인까지 4/4 |
| M6 | 계정·기기(로그인, 기기별 토큰, 페어링 코드) | 구현 완료 |
| M7 | 레이아웃·위젯 엔진 | 부분 — 포맷 v2·드래그 편집기 구현, 위젯 러너 미구현 |
| M8~M10 | 작가·구독·마켓, 외부 공개 | 미착수 |

PoC 완료 기준: 인터넷을 끊은 상태에서도 예약한 07:00에 인쇄되고, 복구 후 앱에 이력이 뜨는 것을 3일 연속. 통과 후 같은 조건으로 30일 연속 운영한다.
