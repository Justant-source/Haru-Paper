## 1. 제품 형태

### 1.1 인라인 어댑터 벽돌

```
[USB-C PD 어댑터] ──C to C──→ [하루종이 디바이스] ──C to C──→ [M832]
                              ┌───────────────────┐
                    USB-C 암  │  긴 가로형, 납작    │  USB-C 암
                    (IN)      │  케이블 라인과 일직선 │  (OUT, 5V 고정)
                              └───────────────────┘
                                       ↑ Wi-Fi로 서버 폴링
```

- **반드시 유선**: 충전기 → 디바이스 → 프린터가 케이블로 이어진다. 디바이스는 전원을 통과시키고 프린터 전원 5V를 만든다.
- **형태**: 옛 노트북 충전기의 어댑터 벽돌. 길고 납작하며 양 끝에 USB-C 암 포트. 케이블이 꺾이지 않고 일직선으로 지나가게 한다. 사용자에게는 "케이블 중간에 있는 어댑터"로 보인다.
- **크기 목표 [기본값, 실측 후 확정]**: 배포 보드 기준 약 80 × 32 × 18mm(가로가 길다), 양산 전용 PCB 55 × 24 × 12mm. 개발은 DevKitC-1 + 브레드보드(케이스 없음).
- 사용자는 Phomemo 앱을 설치하지 않는다. 절전 설정은 출하 전 개발자가 한다.

### 1.2 데이터 경로 — USB 호스트 [기본값 · **사용자 확인 필요**]

케이블이 어차피 지나가므로 **데이터도 그 케이블로** 보낸다. 디바이스가 USB 호스트가 되어 M832(표준 프린터 클래스 7/1/2)에 직접 쓴다.

| 근거 | 상태 |
|---|---|
| M832에 보낼 바이트(헤더·163바이트 행·꼬리)가 USB로 인쇄됨 | [확인됨·실물] detox-printer E-1·E-3 |
| 디스크립터(VID:PID 0483:5740, Bulk OUT 0x02, wMaxPacketSize 64, FS) | [확인됨] `device-descriptor.md` |
| 표준 클래스 `GET_PORT_STATUS`로 용지 감지 후보(H4) | [미검증] — P0에서 0원 시험 |
| BT 특유의 문제(페어링, 거리, 유휴 후 재연결, Wi-Fi/BT 코엑시스턴스, Bluedroid RAM) | USB에서는 **발생하지 않음** |

**Pi PoC와 transport가 다르다는 점을 분명히 한다.** 01의 Pi는 BT(SPP)로 인쇄하고, 이 디바이스는 USB로 인쇄한다. 바이트는 두 경로 모두 [확인됨·실물]이고 transport 계층은 얇다. 역할 분담:

| 01 Pi 30일이 검증하는 것 | 이 계획 P1이 따로 검증해야 하는 것 |
|---|---|
| 서버 스케줄·렌더·동기화, 오프라인 인쇄, 프린터 상시 기상, 용지·보존성, 실패 모드 | 인라인 전원(9V→5V, 2A), USB 열거·claim, Bulk 전송, `GET_PORT_STATUS`, 발열 |

> 이 결정은 "유선 필수"라는 사용자 발언에서 추론한 것이다. **§2 G1의 첫 조건으로 사용자 확인을 받는다.** 확인 전에는 부품을 사지 않는다.

### 1.3 칩 — ESP32-S3, ESP-IDF v5.x

| 후보 | USB 호스트 | 판정 |
|---|---|---|
| **ESP32-S3** | USB OTG(FS) | **채택.** BLE도 있어 절전 설정이 BLE 전용으로 밝혀져도 대응 가능 |
| ESP32-S2 | USB OTG | 가능하나 BLE 없음 |
| ESP32-C3 / C6 | 없음(Serial/JTAG 전용) | 불가 |
| ESP32(오리지널) | 없음 | 불가 (BT 데이터 대안일 때만 후보) |

프레임워크는 **ESP-IDF v5.x LTS 고정**. `usb_host`, OTA 롤백, 프로비저닝이 전부 IDF 네이티브다. Arduino-ESP32에는 USB 호스트 API가 없다. 개발 보드 **ESP32-S3-DevKitC-1 N16R8**(포트 2개: UART·네이티브 USB). 배포는 소형 S3 보드(N8R8 이상, **PSRAM 필수**, GPIO19/20이 헤더에 나오거나 §3.5 실험이 통과한 것).

### 1.4 대안 — 전원만 유선, 데이터는 BT (보존용 한 단락)

USB 호스트가 사용자 확인에서 기각되면: 인라인 전원 회로(§3)는 그대로 두고 데이터만 BT Classic SPP(RFCOMM 채널 1, 01에서 [확인됨·실물])로 보낸다. 이때 칩은 BT Classic이 있는 **원본 ESP32(WROVER, PSRAM 8MB, Bluedroid)**로 바뀌고, `usb_printer.c`가 SPP 클라이언트(Just Works, 채널 1 고정, 혼잡 이벤트 대기, 전송 후 11바이트 응답 read)로 교체되며, Wi-Fi 다운로드 후 Wi-Fi 유휴 상태에서 전송하는 순차 사용과 힙 실측이 P1에 추가된다. 그 외(전원·케이스·스케줄러·PBM)는 동일하다.

## 2. 구매 계획 — 게이트를 통과하기 전에는 아무것도 사지 않는다

### 2.0 원칙

1. 각 구매는 게이트에 묶인다. "배송이 오래 걸리니 미리"는 금지.
2. 수량은 **다음 게이트까지 필요한 만큼만.** "전부 2배수"는 폐기.
3. 케이블·어댑터·공구·프린터는 국내(빠르고 품질 안정). 모듈·브레이크아웃은 알리.
4. **프린터는 1호기 1대로 끝까지 간다.** 혼자 테스트하는 단계에서 2호기를 사지 않는다(사용자 결정). 10대분 프린터는 G3.

### 2.1 게이트와 그 게이트에서 사는 것

| 게이트 | 조건 | 통과 후 사는 것 | 대략 |
|---|---|---|---|
| **G0 지금** | — | **없음** | 0 |
| **G1** | ① **데이터 경로 USB 호스트를 사용자가 확인**(§1.2) ② 서버 `.pbm` 출력 구현 착수 결정 ③ (0원) `GET_PORT_STATUS` 시험 결과 기록(§6 P0) | **개발 1대분**(§2.2) | 약 15~18만 원 |
| **G2** | P1 통과(§9) | 배포용 소형 S3 보드 ×3(회로도 확인 후), 디지털 캘리퍼스, PETG 1롤, M3 열 인서트·M3/M2.5 나사 세트, **3D 프린터(빌드 ≥180mm)** — §5.6 | 약 60~65만 원(프린터가 대부분) |
| **G3** | P4 통과(§9) | 소형 보드 +8, 전원 모듈 세트(트리거·벅·브레이크아웃·폴리퓨즈·TVS) +8, PD 어댑터 30W KC ×12, USB-C C-C 케이블 ×24, **M832 국내 유통 필요 대수** | 프린터가 지배(§7) |

## 3. 전원 설계

### 3.1 블록도

```
[USB-C 암 · IN]  (PD 트리거 보드의 자체 커넥터 사용)
   CC1/CC2 → PD 트리거 → 9V 협상
   VBUS(9V) ──→ 고정 5V 벅 ──→ 5V
                                ├─→ ESP32-S3 (5V 핀)
                                └─→ 폴리퓨즈 3A ──→ [USB-C 암 · OUT] VBUS

[USB-C 암 · OUT]
   VBUS ← 5V 고정 (PD/QC 신호 없음)
   CC1, CC2 ← 각각 10kΩ 풀업(Rp) → 5V/3A 광고
   D+ ←→ ESP32-S3 **GPIO20** (USB_D+)
   D− ←→ ESP32-S3 **GPIO19** (USB_D−)
   D+/D− ← USBLC6-2 TVS (커넥터에 최대한 가깝게)
   GND 공통
```

- **GPIO19 = D−, GPIO20 = D+.** 반대로 물리면 열거가 안 되고 원인이 보이지 않는다.
- 10kΩ Rp → 3A 광고(56k 기본, 22k 1.5A, 10k 3A).
- 입력 측 커넥터는 트리거 보드에 있으므로 브레이크아웃은 출력 측에만 쓴다.

### 3.2 핵심 제약

| 항목 | 값 | 근거 |
|---|---|---|
| 다운스트림 전압 | **5V 고정** | M832는 5V 2A만, 고속충전 미지원 [확인됨·Phomemo KB] |
| 다운스트림 PD 소스 | 넣지 않는다 | 동일 |
| 업스트림 | **PD 9V** | 5V 3A는 케이블 전압강하로 불안정. 12V는 PD 선택 사항 |
| 번들 어댑터 | 30W 이상, 9V PDO | |
| 비PD 어댑터 삽입 | 트리거 5V 폴백 → 벅 드롭아웃 → 4.5~4.8V | 충전이 약해진다. "동봉 어댑터만 사용" 안내 + 케이스 각인 |

### 3.3 전력 예산·발열

통과 전력(최대 10W)은 디바이스에서 소산되지 않는다. 디바이스 자체 발열은 벅 손실 + ESP32뿐.

| 항목 | 최악(배터리 급속 충전) | 정상(만충, 기상 대기) |
|---|---|---|
| M832 인입 | 10W(통과) | 0.5~1.5W(통과) [추정] |
| 벅 손실(효율 ~90%) | ~1.1W | ~0.2W |
| ESP32-S3(Wi-Fi + USB 호스트) | 0.6~1.5W | 0.6~1.0W |
| **디바이스 자체 발열** | **약 2~2.5W** | **약 1W** |

80×32×18mm 케이스에서 2.5W는 표면이 미지근한 정도. 통풍 슬롯은 넣되 설계 제약이 아니다. **P1에서 USB 전력계로 M832 정상 상태 인입 전력을 실측**해 [추정]을 채운다.

### 3.4 D+/D− 배선

- M832는 USB Full Speed(wMaxPacketSize 64 [확인됨]). S3 루트 포트도 FS 전용.
- D+/D− 쌍은 **5cm 이내, 나란히, 꼬아서.** 전원선과 나란히 길게 가지 않게.

### 3.5 프린터 연결 전 검증 절차 — 필수

**M832는 1대뿐이다.** 전원 회로가 확인되기 전에는 절대 물리지 않는다.

1. PD 트리거 단독: 어댑터 연결 → 멀티미터로 **9V** 확인
2. 벅 연결: 무부하 출력 **5.0~5.15V**
3. 부하: 2.5Ω/10W 저항 → **2A에서 4.9V 이상** 유지, 벅 모듈 온도 손으로 확인
4. ESP32 연결 후 Wi-Fi 활성 상태에서 재측정
5. 여기까지 통과해야 프린터를 물린다

**선택 실험 — 소형 보드의 자체 USB-C를 OUT 포트로**: 소형 S3 보드는 대개 USB-C의 VBUS가 보드 5V 네트에, D+/D−가 GPIO19/20에 직결돼 있다. 벅 5V → 보드 5V 핀 → 보드 USB-C → C to C → M832로 이으면 브레이크아웃·D+/D− 손배선·Rp가 사라진다. 조건: VBUS-5V 사이 다이오드 없음(회로도). 리스크: 보드 VBUS 트레이스가 2A를 못 견딜 수 있다 → 2A 부하에서 트레이스 온도·전압강하 실측 후 판단. P1에서 30분. 성공하면 P3 조립이 단순해진다.

## 4. 펌웨어 설계

### 4.1 원칙 — Pi 에이전트의 축소판

```
서버:  포맷·예약 저장 → 프로필 폭으로 렌더 → PNG(앱 미리보기) + PBM 1-bpp(기기용)
       /api/device/{poll, snapshot, renders/{id}.pbm, results}
기기:  poll(30s) → 스냅샷(예약·렌더 목록) 캐시 → PBM 다운로드·sha256 검증·캐시
       → 로컬 시계로 occurrence 계산 → 용지 정책 → PBM 행 → 163바이트 행 + 헤더·꼬리 → USB Bulk OUT → 결과 대기열 → 업로드
```

- **인터넷이 끊겨도 예약 시각에 인쇄한다**(PoC 완료 기준). 스케줄러·캐시가 기기에 있다.
- **m832를 아는 코드는 기기뿐**(`CLAUDE.md` 경계). 서버는 프로필(`model, dpi, paperWidthMm, printableWidthPx`)만 안다. 서버의 PBM은 프린터 무관한 범용 1-bpp 출력이다.
- 기기가 보유하는 상태: Wi-Fi 자격증명·기기 토큰(NVS), 스냅샷·PBM 캐시·결과 대기열(플래시), CA 번들(펌웨어).

### 4.2 이미지 — 서버 1-bpp(PBM) 채택

규약(`docs/architecture.md`): `GET /api/device/renders/{renderId}.pbm` — **PBM P4**, 폭 = `printableWidthPx`, 1 = 검정, MSB-first, 서버가 Floyd–Steinberg. 스냅샷 `renders[]`에 `urlPbm`·`sha256Pbm`. **펌웨어에 PNG 디코더·디더링이 없다.**

기기 변환(`image_m832.c`), 상수마다 근거 주석:

| 단계 | 내용 | 근거 |
|---|---|---|
| PBM 파싱 | `P4\n<w> <h>\n` 뒤 packed rows, 행 stride = ceil(w/8) | 규약 |
| 좌우 정렬 보정 | 행마다 **`00 00 00`(3바이트 = 24dot = 2.0mm) prepend + 앞 160바이트 → 163바이트**. 비트 시프트 없음(24dot가 정확히 3바이트) | Pi `apply_h_offset` [확인됨·실물], 좌우 여백 대칭 약 1mm |
| 헤더 | `1F 11 0B` + `1F 11 35 00` + `1D 76 30 00 xL xH yL yH`(xL/xH = 163, yL/yH = 행 수, LE) | detox-printer `protocol.md` [확인됨·실물] |
| 꼬리 | `1B 64 01` + `1B 64 02` + `1F 11 11` | 동일 |

`printableWidthPx`가 1300이면 PBM 행이 163바이트라 뒤 3바이트가 잘리고, 1280으로 확정되면 160바이트라 3 + 160 = 163으로 잘림 없이 맞는다(`docs/pi/printer-m832.md` 4절 후보 B). 어느 쪽이든 기기 코드는 같다.

### 4.3 USB 호스트 구현

ESP-IDF `usb_host` 라이브러리. 표준 프린터 클래스라 전용 드라이버가 없다.

```
1. usb_host_install() — 데몬 태스크에서 usb_host_lib_handle_events() 루프
2. 클라이언트 등록 → 디바이스 연결 이벤트 → usb_host_device_open()
3. Configuration Descriptor 파싱(라이브러리가 SET_CONFIGURATION 수행)
4. bInterfaceClass == 7 인터페이스 → usb_host_interface_claim()
5. Bulk OUT 0x02 확보
6. (H4 통과 시) GET_PORT_STATUS 컨트롤 전송 1회로 용지 확인:
   bmRequestType 0xA1, bRequest 0x01, wIndex = 인터페이스, wLength = 1 → bit5 Paper Empty, bit3 Not Error
7. usb_host_transfer_submit()으로 청크 전송(완료 콜백 → 세마포어 직렬화). 청크 4096 시작 [확인됨·실물, detox-printer E-1 pyusb·V2 RFCOMM 동일값]
8. 전체 write 데드라인 60초. 초과 시 `failed`, 재발행 없음
```

| 유리한 조건 | 상태 |
|---|---|
| 표준 프린터 클래스 7/1/2 | [확인됨] |
| 전송 후 Bulk IN 무응답이어도 인쇄됨 | [확인됨·실물] |
| 청크 4096, 페이싱 불필요 | [확인됨·실물] |
| Full Speed | [확인됨] |

**난이도**: 디스크립터가 있고 같은 바이트가 Pi·USB에서 찍히므로 소프트웨어는 1주 안팎. 나머지는 손배선 신호·전원이다. 열거가 안 되면 순서: ① D+/D− 뒤바뀜 ② 브레이크아웃 A6/B6 미결선 ③ 5V 레일 흔들림 ④ 그 다음이 코드.

### 4.4 로컬 스케줄러·캐시·결과 대기열 (`docs/pi/agent.md` 축소판)

| Pi 에이전트 | 이 디바이스 |
|---|---|

### 4.5 메모리·플래시

- **PSRAM 8MB**: PBM 페이지(163 × 행 수, 1725행이면 281KB)를 `heap_caps_malloc(MALLOC_CAP_SPIRAM)`으로 통째 수신 → mbedtls sha256 누적 → 일치할 때만 전송. 반쪽 래스터 방지.
- **USB 전송 버퍼는 내부 RAM**: `usb_host_transfer_alloc()`의 DMA 버퍼(4~16KB)로 PSRAM에서 memcpy.
- 내부 RAM: Wi-Fi + TLS + `usb_host` + (조건부) NimBLE. `CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC`로 TLS를 PSRAM으로.
- **플래시 8MB 이상**: OTA A/B 2슬롯 + 데이터 파티션(스냅샷, PBM 캐시 2~3장, 대기열) ≥ 2MB. N16R8이면 여유.

### 4.8 필드 배포 필수 항목

Pi는 Tailscale 안에서 SSH가 됐다. 지인 집의 디바이스는 원격 로그·OTA 말고 손댈 방법이 없다. P5 전에 전부.

| 항목 | 내용 |
|---|---|
| **서버 공인 HTTPS** | ESP32는 Tailscale에 못 붙는다. **03 플랫폼 M10(공인 도메인 + TLS 종단)과 하나로 진행**, 서버 설정 변경이라 **사용자 승인**. 기기별 토큰·레이트리밋은 M6 구현됨 |

| 토큰·프로비저닝 | 캡티브 포털 "HaruPaper-XXXX"에서 Wi-Fi + **페어링 코드** → `POST /api/device/pair` → 토큰 NVS [기본값, 03 Q14 구현 시]. 아니면 개발자가 NVS 주입 |

| 자가 복구 | 30분 poll 실패 시 재부팅, Wi-Fi 무한 재접속, USB 장치 없음은 `skipped_printer_offline` 후 유예 내 재시도 |

### 4.9 방어 로직 (`docs/pi/policy.md` 정합)

- 중복 방지는 기기 로컬(occurrence key, command id, `final`). 전송 도중 죽으면 재시작 후 **자동 재인쇄 없이 `failed`** — "안 나옴 ≥ 두 장 나옴".
- 결과 업로드는 `resultId` 멱등. 명령 완료도 결과로 보고. 서버 명령은 10분 뒤 만료.
- 시각은 로컬(KST), `serverTime`과 크게 어긋나면 경고만.
- **디바이스는 항상 깨어 있다.** USB 호스트는 슬립과 양립하지 않는다. 핑·로드 스위치·VBUS 제어·배터리 제어 없음(절전 "안함"이 재부팅 후 유지됨 [확인됨·실측]).

## 5. 케이스 — 3D 프린팅 제작 과정

긴 가로형이라 **케이스 길이가 110mm 안팎**이다. 3D 프린터 빌드 ≥180mm 조건이 실제로 중요하다.

### 5.1 실측 (캘리퍼스, G2 부품 도착 직후)

배포 보드 외형·나사 구멍·USB-C 돌출, PD 트리거 보드, 벅 모듈, 브레이크아웃, **케이블 플러그 하우징 길이·굵기**(꺾임 여유 계산의 입력값), LED·버튼 위치. 값은 CAD 코드의 변수 파일에 적는다.

### 5.2 배치·모델링 (build123d / CadQuery, git)

1. 부품을 직육면체 더미로 모델링, 치수는 전부 변수
2. **일직선 배치**: IN 포트(트리거 보드 커넥터) — 벅 — 보드 — OUT 포트(브레이크아웃)를 길이 방향으로. 케이블이 양 끝에서 **꺾임 없이** 나간다. 케이블 꺾임 여유 ≥15mm
3. Wi-Fi 안테나 주변 금속 없음 — 보드 안테나가 벅·케이블 쪽을 향하지 않게
4. **IN/OUT 오삽입 방지**: 양쪽이 같은 USB-C 암이라 반대로 꽂을 수 있다. 컴플라이언트 PD 어댑터면 무해하지만 비표준 5V 어댑터를 OUT에 꽂으면 벅에 역전압. → **색상 링 + "IN / OUT" 각인 + 포트 주변 형상 차이**(한쪽만 경사면 등) + 안내 그림
5. 버튼 구멍(프로비저닝 리셋), LED 라이트 파이프 구멍, 통풍 슬롯(§3.3 — 필수 아님)
6. USB-C 커넥터 주변 보강(스트레인 릴리프, 하단 지지 리브)
7. 상하 2분할, M3 나사 4개, 열 인서트 자리
8. 각인: 제품명 / 5V 2A OUT / "동봉 어댑터만 사용" / 기기 ID 라벨 자리
9. 외피 셸 생성 → 슬라이서용 STL/3MF 내보내기

### 5.3 수치 기준

| 항목 | 값 |
|---|---|
| 부품 주변 여유 | 0.3~0.5mm |
| 벽 두께 | 1.6~2.0mm |
| M3 나사 통과 구멍 | 3.3mm |
| 열 인서트 너트 구멍 | 4.1mm |
| 재질 | **PETG** |
| 레이어 / 인필 / 벽 | 0.2mm / 15% / 3줄 |

### 5.4 테스트 쿠폰 → 전체 출력

1. **테스트 쿠폰**: 커넥터 포켓·나사 구멍·인서트 구멍만 잘라낸 작은 조각을 출력해 실물 부품을 끼워 본다. 처음 1~2회는 **출력 대행**(2~5일)으로 CAD 치수를 확인한다
2. 쿠폰이 맞으면 상하 셸 전체 출력. 프린터 세팅(베드 레벨링, PETG 온도·스트링)은 그 자체로 1~2주짜리 일이므로 쿠폰이 맞기 전에는 시작하지 않는다
3. 출력 후 확인: 휨(PETG 길이 110mm는 휘기 쉽다 — 브림·인클로저), 포트 포켓 치수, 각인 가독성

### 5.5 후가공·조립

1. 서포트 제거, 포트 포켓 다듬기
2. 열 인서트 삽입(인두 온도 조절)
3. 트리거·벅·보드·브레이크아웃 고정, D+/D− 5cm 이내 꼬아서 배선, TVS 커넥터 옆
4. **§3.5 검증**을 케이스 안에서 다시 1회(1~3단계)
5. 상하 결합, M3×4
6. 체크리스트: 양 끝 케이블 일직선으로 빠지는가 / 오삽입 표시가 보이는가 / 버튼·LED 동작 / 표면 온도(§3.3) / 케이블 당겼을 때 커넥터 유동 없음

### 5.6 3D 프린터 구매 시점 [기본값]

**P2 착수 시(G2)**. 지금 사면 P0~P1 동안 놀고 세팅이 부업이 된다. 쿠폰 1~2회는 대행으로 먼저 확인하고, 10대 + 반복 출력이 확정된 P2에서 산다. 조건: 빌드 ≥180mm, PETG 가능(인클로저 있으면 유리). PETG 1롤.

| **P3 2~3대 조립** | 1~2주 | 배포 보드 + 케이스. 페어링 코드로 등록. 1대당 1~2시간 | 1호기로 검사 |

| **P5 10대** | 2~3주 | G3 발주 → 조립 → 지인 베타. 안내서 1장 | 10대분 |

**순차 합계 약 5개월, 30% 버퍼 포함 5.5~6.5개월.** 시간을 먹는 곳은 코드가 아니라 손배선 디버깅(P1), 케이스 반복(P2), 10대 수작업(P3·P5), 그리고 **프린터 1대 순서 제약**이다.

### 마일스톤 판정

- P1 완료 = **인라인 전원 + USB 호스트 하드웨어 불확실성**이 사라지는 지점(프로토콜은 01에서, 바이트는 detox-printer에서 이미 확인)
- P4 완료 = 300대 판단 지점
