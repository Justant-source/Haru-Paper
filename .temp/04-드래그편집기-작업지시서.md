## 0. 결정 (확인됨)

| # | 결정 |
|---|---|
| 1 | **범위**: 지금 배포된 편집기부터 순서대로. M7(위젯 스크립트·러너·마켓)이 오면 같은 상호작용 모델을 재사용한다 — 지금은 위젯 스크립트 시스템을 만들지 않는다 |
| 2 | **드래그 방식**: dnd-kit 도입(터치 우선, 포인터 이벤트 기반) |
| 3 | **드래그 조작 범위**: 팔레트→캔버스 드래그로 추가, 기존 항목 드래그로 순서 재배치, 드래그로 폭(1/1, 1/2+1/2 등) 조정, 드래그로 삭제(휴지통 드롭) |

### 이 결정이 만드는 파생 결정 (사용자에게 다시 묻지 않고 여기서 정한다)

- **"폭 조정"은 지금 스키마(schemaVersion 1)로 불가능하다** — 지금 블록은 세로로만 쌓이는 평평한 배열이고, 한 줄에 2개를 나란히 두는 "행" 개념이 없다(이건 M7 계획서 5.1절에만 있었다). 따라서 **M7의 행/슬롯 레이아웃 모델만 지금 당겨온다** — 위젯 스크립트·러너·마켓(M7 5.3~5.4)은 그대로 미루고, 지금 있는 블록 4종을 행/슬롯 컨테이너에 담는 선에서 `schemaVersion 2`로 올린다
- **편집/미리보기 탭 분리를 없앤다** — 지금은 편집 탭(폼 목록)과 미리보기 탭(1초 디바운스 PNG)이 분리되어 있어 "드래그하면서 바로 결과를 본다"가 불가능하다. 편집 탭 자체를 종이 비율의 캔버스로 바꾸고, 그 캔버스에서 드래그가 일어난다. 서버 PNG 미리보기(정확한 인쇄 결과)는 캔버스와 별개로 버튼 하나로 계속 쓸 수 있게 둔다 — 드래그 중 매번 서버를 부르면 느리고 배터리도 먹는다
- **폭 조정의 정확한 형태**: 자유 드래그(임의 픽셀)가 아니라, 2슬롯 행 가운데의 손잡이를 좌우로 드래그하면 정해진 3개 비율(1/2·1/2 / 2/3·1/3 / 1/3·2/3)에 스냅된다. 이유: 손가락으로 정확한 픽셀 비율을 맞추는 건 신뢰할 수 없고, 스키마도 이 4개 조합만 허용한다(M7 5.1과 동일)
- **삭제**: 슬롯을 화면 아래 "휴지통" 드롭존으로 끌면 삭제. 실수 방지로 5초짜리 되돌리기(Undo) 토스트를 띄운다

## 1. 원칙

1. **드래그 중 서버를 부르지 않는다.** 캔버스는 순수 클라이언트 렌더링(CSS)이고, `FormatDocument` state가 바뀌는 즉시 다시 그린다. 서버 PNG는 "정확히 보기" 버튼을 눌렀을 때만(기존 1초 디바운스 메커니즘 그대로 재사용)
2. **블록 계약(Block: type/props/style)은 바꾸지 않는다.** 바뀌는 건 블록들을 담는 컨테이너(행/슬롯)뿐. `TextBlockForm` 등 블록별 속성 편집 폼 4개는 그대로 재사용한다
3. **기존 저장된 포맷(schemaVersion 1)을 깨지 않는다.** 읽을 때 자동으로 2로 변환(up-convert)하고, 저장은 항상 2로 나간다. 일괄 마이그레이션 스크립트나 DB 변경은 필요 없다(`body`는 JSON 문자열 컬럼이라 스키마 변경이 아니라 그 안의 구조만 바뀐다)
4. **새 의존성은 dnd-kit 계열 하나만.** Tailwind나 새 UI 킷은 여전히 금지(우드톤 리디자인 규칙 유지). 기존 CSS 변수·컴포넌트(Card, Button, BottomSheet 등)를 그대로 쓴다
5. **모바일 우선.** 캔버스는 셸 480px 안에서 동작해야 하고, 드래그는 포인터 이벤트라 터치·마우스 둘 다 된다(dnd-kit이 처리)

## 2. 데이터 모델 — schemaVersion 2

```json
{
  "schemaVersion": 2,
  "meta": { "name": "아침 종이", "author": "…" },
  "style": { "fontFamily": "Pretendard", "baseFontSizePt": 11, "lineHeight": 1.4, "marginMm": {...}, "blockGapMm": 3, "divider": "none" },
  "rows": [
    { "id": "r1", "slots": [
      { "id": "s1", "width": "1/1", "block": { "type": "dateHeader", "props": {"pattern": "M월 D일 dddd"}, "style": {"align": "center"} } }
    ]},
    { "id": "r2", "slots": [
      { "id": "s2", "width": "2/3", "block": { "type": "text", "props": {"text": "..."}, "style": {} } },
      { "id": "s3", "width": "1/3", "block": { "type": "weather", "props": {"fields": ["tempMin","tempMax"]}, "style": {} } }
    ]}
  ]
}
```

| 필드 | 규칙 |
|---|---|
| `rows` | 최상위. `blocks`(평평한 배열)를 완전히 대체한다. 1~30개 [기본값, M7 5.1과 동일] |
| `row.id` | 편집기 안에서만 쓰는 문자열 id(uuid). 저장 시 그대로 유지, 서버는 존재만 확인(형식 검증 없음) |
| `row.slots` | 1~2개 |
| `slot.id` | 마찬가지로 편집기 내부 id |
| `slot.width` | 슬롯 1개짜리 행이면 `"1/1"`만 허용. 슬롯 2개짜리 행이면 `("1/2","1/2")` \| `("2/3","1/3")` \| `("1/3","2/3")`만 허용 — 그 외 조합은 422 |
| `slot.block` | 기존 `Block`(type/props/style) 그대로. **`null`은 허용 안 함** — 빈 슬롯을 만들지 않는다(슬롯이 생기는 순간 블록이 있어야 함, 팔레트에서 드래그로 만들 때 항상 블록과 함께 생성됨) |

**Up-convert (1 → 2)**: 기존 `blocks: Block[]` 각 항목을 `{id: uuid(), slots: [{id: uuid(), width: "1/1", block: 그 블록}]}` 행 하나로 감싼다. 순서 그대로 유지.

**어디서 up-convert하나**: 지금 `format.getBody()`를 직접 `objectMapper.readValue(..., FormatDocument.class)`로 역직렬화하는 곳이 최소 2군데다(`FormatService`의 조회 경로, `RenderScheduler.parseFormatDocument`). **이 둘을 포함해 저장된 body를 읽는 모든 지점**이 반드시 하나의 공용 함수를 거쳐야 한다 — 안 그러면 v1으로 저장된 기존 포맷(운영 DB에 실제로 여러 개 있다)이 렌더 스케줄러에서만 깨지는 식의 사고가 난다. `FormatDocumentSupport`(이미 있는 클래스, `hasDynamicBlocks` 등을 둔 곳)에 `readDocument(String bodyJson, ObjectMapper mapper)` 정적 메서드를 만들고, **body를 읽는 모든 곳을 grep해서** 그 메서드로 교체한다.

**검증(쓰기 경로만)**: `FormatValidator`는 이제 `schemaVersion == 2`만 허용(기존의 "정확히 1 아니면 422" 규칙을 그대로 "정확히 2"로). 읽기 경로(위 up-convert)는 검증기를 거치지 않는다 — 이미 저장된 데이터는 신뢰한다.

### 3.3 `SlotContent` props (LayoutCanvas와 렌더러 사이의 유일한 접점)

```ts
// app/web/src/format-editor/SlotContent.tsx
export function SlotContent({
  block,
  printerWidthPx,   // 현재 프린터 프로필 폭(px). 없으면 PrinterProfile.DEFAULT 폭 사용
  slotWidthFraction, // 0.5, 0.667, 0.333, 1 — 이 슬롯이 행에서 차지하는 비율
}: {
  block: Block
  printerWidthPx: number
  slotWidthFraction: number
}): JSX.Element
```

- text: `block.style.fontSizePt`(없으면 전체 `FormatStyle.baseFontSizePt`)를 `layout-math.ts`의 `ptToPx(pt, dpi)`로 변환해 `font-size`로 씀. 서버 `HtmlTemplateBuilder.convertPtToPx`와 **같은 공식**(pt/72×dpi)
- image: `assetId`로 `GET /api/assets/{id}` 이미지를 그대로 `<img>`(에셋은 업로드 시점에 이미 존재하므로 네트워크 호출 있음 — 드래그 자체와는 무관하니 원칙 1 위반 아님)
- dateHeader: 오늘 날짜로 패턴 치환한 텍스트(서버 `formatDateHeader`와 같은 토큰 규칙 — `M월 D일 dddd` 등, `docs/server/format-schema.md` 참고)
- weather: 실제 날씨 데이터 없음 — `"날씨 (인쇄 시점에 채워짐)"` 같은 플레이스홀더만 표시

`layout-math.ts`(`app/web/src/lib/layout-math.ts`, 신규): `mmToPx(mm, dpi)`, `ptToPx(pt, dpi)` 두 함수만. 서버 `HtmlTemplateBuilder`의 공식과 반드시 일치시킨다(mm/25.4×dpi, pt/72×dpi).

### 에이전트 1 — 백엔드: schemaVersion 2

**파일**: `server/src/main/java/com/harupaper/server/format/` 전체(신규 `Row.java`, `Slot.java` 추가, `FormatDocument.java`, `FormatValidator.java`, `FormatDocumentSupport.java`, `FormatService.java` 수정), `server/.../render/HtmlTemplateBuilder.java`, `server/.../render/RenderScheduler.java`(body 읽는 부분만)

- `Row(String id, List<Slot> slots)`, `Slot(String id, String width, Block block)` record 추가
- `FormatDocument.blocks` → `rows`로 교체(2절 JSON 그대로)
- `FormatValidator`: `schemaVersion == 2`만 허용. 슬롯 폭 조합 검증(2절 표), 행 1~30개, 슬롯 1~2개, `slot.block`이 null이면 422
- `FormatDocumentSupport.readDocument(String bodyJson, ObjectMapper mapper)`: schemaVersion이 1이면 up-convert(2절), 2면 그대로 파싱. **`format.getBody()`를 직접 역직렬화하는 모든 곳**(`grep -rn "readValue.*FormatDocument" server/src/main/java`로 찾아라)을 이걸로 교체 — `RenderScheduler.parseFormatDocument`가 특히 중요(지금 자체 역직렬화 로직이 있다)
- `HtmlTemplateBuilder.generateHtml`: 블록을 순회하던 루프를 행→슬롯 이중 루프로 바꾼다. 한 행에 슬롯 2개면 flex/grid로 나란히(`display:flex`, 각 슬롯 `flex: 0 0 {width}%`), 슬롯 사이 여백은 없음(붙어 있음 — 필요하면 [기본값]으로 4mm), 행 사이 간격은 기존 `style.blockGapMm` 그대로, `divider`도 행 사이에 기존처럼
- 기존 단위 테스트(`RenderSchedulerDynamicReRenderTest`, `WeatherSettingsChangeTest` 등) 중 `format.setBody("{\"schemaVersion\": 1, ... \"blocks\": [...]}")` 같은 v1 픽스처를 쓰는 곳은 **그대로 둬도 된다** — up-convert가 자동으로 처리하므로 테스트가 깨지면 안 된다. 깨지면 up-convert 로직이 빠진 곳이 있다는 뜻이니 다시 찾아라
- **`docs/server/format-schema.md`를 이 절 내용대로 갱신**(schemaVersion 2, rows/slots, up-convert 절차) — 서버 세션 담당 문서다

### 에이전트 2 — 프런트: 드래그 핵심(캔버스·팔레트·리사이즈·삭제)

**신규 파일**: `app/web/src/format-editor/LayoutCanvas.tsx`, `app/web/src/format-editor/WidgetPalette.tsx`

- `DndContext`(dnd-kit) 하나로 팔레트와 캔버스를 감싼다(팔레트→캔버스 드롭이 되려면 같은 컨텍스트여야 한다)
- `LayoutCanvas` props: `{ rows: Row[], onChange: (rows: Row[]) => void, onSelectSlot: (rowId: string, slotId: string) => void, printerWidthPx: number }`. 내부에서 3.2절의 `SlotCard`/`ResizeHandle`/`TrashZone`을 그린다. `SlotContent`(에이전트 3 산출물)를 import해서 슬롯 안에 렌더 — **3.3절 props로만 호출**(에이전트 3이 아직 안 끝났어도 그 인터페이스로 먼저 짜고 나중에 맞춘다)
- 순서 재배치: `@dnd-kit/sortable`의 `SortableContext` + `arrayMove`로 슬롯/행 배열을 조작. 슬롯을 다른 행으로 드래그하면 그 행에 슬롯이 추가되고(2개 넘으면 안 받음 — 드롭 불가 표시), 원래 있던 행이 비면 행 자체를 없앤다
- 리사이즈: `ResizeHandle`은 2슬롯 행에서만 렌더, 가운데 좌우로 드래그하면(포인터 이벤트, dnd-kit 없이 직접 구현해도 됨 — 리사이즈는 sortable이 아니라 별도 제스처) `TWO_SLOT_WIDTH_PAIRS` 중 가장 가까운 조합으로 스냅, `onChange`로 두 슬롯의 `width`를 같이 바꾼다
- 삭제: 슬롯을 `TrashZone` 위로 드래그해서 놓으면 그 슬롯 제거(행이 비면 행도 제거) + 5초 Undo 토스트(그 사이 상태를 메모리에 들고 있다가 "되돌리기" 누르면 복원)
- `WidgetPalette`: 블록 타입 4개 카드, `useDraggable`. 드롭되면 `newRow(newBlock(type))`(에이전트 5가 `newRow` 헬퍼를 types/format.ts에 이미 넣어뒀다)로 새 행을 만들어 드롭 위치에 삽입. 캔버스 맨 위/맨 아래 또는 기존 행 사이에 드롭 가능
- CSS 클래스는 **3.4절 이름 그대로** JSX에 붙인다(스타일 자체는 6번이 채운다 — 지금은 안 예뻐도 된다, 구조와 동작이 맞으면 된다)

### 에이전트 3 — 프런트: 클라이언트 구조 렌더러

**신규 파일**: `app/web/src/lib/layout-math.ts`, `app/web/src/format-editor/SlotContent.tsx`

- `layout-math.ts`: `mmToPx`, `ptToPx` (3.3절 공식)
- `SlotContent.tsx`: 3.3절 props 그대로 구현. `docs/server/format-schema.md`의 dateHeader 패턴 토큰 표를 그대로 프런트에 재현(서버 `formatDateHeader`와 같은 결과가 나와야 시각적으로 안 어긋난다)
- `printerWidthPx`는 어디서 오나 — `FormatEditPage`가 `GET /api/device`(기존 앱용 엔드포인트, 이미 있다)로 `printerProfile.printableWidthPx`를 읽어 내려준다(없으면 `PrinterProfile.DEFAULT` 폭 [기본값] 110mm/300dpi 환산값을 이 파일에 상수로 박아둬라 — 서버 `PrinterProfile.DEFAULT`와 같은 값인지 `server/.../device/PrinterProfile.java` 확인)
- 이 파일들은 `LayoutCanvas`가 import해서 쓰므로, 에이전트 2와 **파일이 겹치지 않지만 인터페이스가 겹친다** — 3.3절 시그니처를 절대 벗어나지 마라

### 에이전트 4 — 프런트: FormatEditPage 재조립 + 속성 편집 시트

**파일**: `app/web/src/pages/FormatEditPage.tsx`(재작성), 삭제 대상 파일 정리(`app/web/src/format-editor/BlockList.tsx` 제거), `app/web/src/format-editor/Preview.tsx`(수정, 아래 참고)

- 상태 모양을 `blocks: Block[]` → `rows: Row[]`로 바꾼다(로컬 `useState`, react-query 아닌 지금 방식 유지)
- 탭 2개(편집/미리보기) 구조를 없애고, 편집 화면 자체를 `LayoutCanvas`(에이전트 2)로 채운다
- 슬롯을 탭하면(드래그 아님, `onSelectSlot`) 기존 `TextBlockForm`/`ImageBlockForm`/`DateHeaderBlockForm`/`WeatherBlockForm` + `BlockStyleForm`을 **그대로 재사용**해서 BottomSheet로 편집 폼을 띄운다(지금 있는 컴포넌트, 바꿀 필요 없음 — props만 "선택된 블록"에서 "선택된 (rowId,slotId)의 블록"으로 바뀐다)
- "정확히 보기" 버튼: 기존 `Preview.tsx`의 디바운스+blob 로직(`POST /api/formats/preview`)을 재사용하되, 항상 보이는 탭이 아니라 **버튼을 눌렀을 때 모달/시트로 PNG를 보여주는 방식**으로 바꾼다(`Preview.tsx` 자체는 로직 대부분 유지, 트리거 방식만 변경)
- 저장(`formatsApi.create/update`)은 그대로, body에 `rows`가 실려 나가는 것만 다르다
- 미저장 변경 확인(`beforeunload`, 나가기 확인 시트)은 그대로 유지
- `docs/app/screens.md`의 "(2) 포맷 편집" 절을 이 구조대로 갱신(탭 2개 → 캔버스+버튼) — **문서는 다른 에이전트와 안 겹치니 이 에이전트가 씀**

### 에이전트 5 — 프런트: 저장 대상 정리 + 에셋/기기 연동

**파일**: `app/web/src/api/formats.ts`(있다면, body 타입만 `rows` 기준으로 자동 반영 — 대부분 손댈 것 없음, 확인만), `app/web/src/api/device.ts`(printerProfile 조회 노출 확인), `app/web/src/format-editor/blocks/ImageBlockForm.tsx`(에셋 선택 흐름이 새 구조에서도 동작하는지 확인·필요시 소폭 수정), 그 외 `rows`로 바뀐 타입 때문에 컴파일이 깨지는 나머지 파일 전부(`grep -rn "\.blocks\b" app/web/src --include=*.tsx --include=*.ts`로 찾아서 고쳐라 — `FormatListPage.tsx`의 요약 표시 등 `blocks` 참조가 남아있는 곳)

- 이 에이전트의 진짜 임무는 **"컴파일 청소부"**다 — 에이전트 2/3/4가 새로 만드는 파일 밖에서, `Block[]`이던 게 `Row[]`로 바뀌어서 깨지는 나머지 전체를 훑어 고친다. `npm run build`를 반복 돌려서 에러가 0이 될 때까지(단, 에이전트 2/3/4가 담당하는 신규 파일 안의 에러는 무시 — 그건 그쪽 몫)
- 특히 `FormatListPage.tsx`가 `document.blocks`나 `hasDynamicBlocks` 판정에 쓰는 게 있으면 `document.rows`의 슬롯을 순회하도록 고쳐라

### 에이전트 6 — i18n + CSS

**파일**: `app/web/src/i18n/ko.ts`, `app/web/src/i18n/en.ts`, `app/web/src/index.css`

- 3.5절 키를 ko.ts/en.ts에 추가(다른 화면 톤 참고해서 문구 정하기)
- 3.4절 클래스에 실제 스타일 채우기: 캔버스는 기존 `.paper-frame` 비율 재활용, 행은 `display:flex; gap: 0`, 슬롯은 `flex-basis`를 인라인 style로 받으므로 CSS는 테두리·패딩·드래그 중 스타일만, 리사이즈 손잡이는 폭 44px 이상(접근성 규칙, 이 저장소 관례), 휴지통 드롭존은 화면 하단 고정 + 드래그 중일 때만 `opacity`/`transform`으로 나타나게, undo 토스트는 기존 토스트/배너 패턴(`banner banner-warn` 등) 참고해서 새로 만들되 자동 사라짐 애니메이션
- 기존 `.block-list`/`.block-item`/`.add-block-menu-item`류(이제 안 쓰임)는 **에이전트 4가 `BlockList.tsx`를 지운 뒤에** 죽은 CSS인지 확인하고 지워라(다른 곳에서 재사용 중이면 남겨둔다 — grep으로 확인)
- **이 에이전트는 다른 에이전트의 완료를 기다리지 않는다** — 3.4/3.5절 계약만 보고 먼저 채워 넣는다. 나중에 클래스명이 실제 JSX와 안 맞으면 내가 통합 단계에서 고친다
