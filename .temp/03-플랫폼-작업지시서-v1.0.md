## 2. 원칙 (이 지시서 전체에 적용, 어기지 말 것)

1. **사용자 스크립트는 `haru-widget-runner` 컨테이너 밖에서 실행하지 않는다.** JVM 안에서 사용자 JS를 돌리지 않는다.
2. **스크립트는 HTML/CSS/SVG를 만들 수 없다.** 출력은 4절 블록 어휘 JSON뿐이며 서버 검증기를 통과해야 렌더된다. 검증 실패 = 위젯 실패(Q9 재배치).
3. **스크립트에 네트워크·파일·타이머·난수 시드 없음.** 필요한 데이터는 `manifest.data` 선언에 따라 **서버가 미리 채워** `ctx`로 넘긴다.
4. **종이가 안 나오는 상태를 만들지 않는다.** 슬롯 전부가 실패해도 날짜 + 안내 한 줄짜리 대체 페이지를 인쇄한다 [기본값].
5. **Pi 규약(`/api/device/{poll,snapshot,renders,results}`)의 요청·응답 형태는 바꾸지 않는다.** 바뀌는 건 인증(기기별 토큰)과 서버 내부뿐. PoC가 끊기면 안 된다.
6. **M832·프로토콜 상수는 여전히 `/pi/printer/m832`에만.** 서버·앱은 프린터 프로필(`widthMm`, `printableWidthPx`, `dpi`)만 안다.
7. **`/pi`, `/docs/pi`는 수정하지 않는다.** 필요한 Pi 변경은 `.temp/` 인계 메모로 노트북 세션에 넘긴다.
8. **공개 저장소**다. 비밀값은 `.env`에만. 커밋 전 `git diff --cached`.
9. `CLAUDE.md`·`docs/architecture.md`·`.gitignore`는 공통 파일 — 수정 직전 `git pull --ff-only`, 실패 시 멈추고 보고.
10. 마일스톤 통과 조건을 만족하기 전에 다음 마일스톤으로 넘어가지 않는다.

**`CLAUDE.md` 개정안** (M6 착수 시 적용):
- "범위(PoC)" → "**하드웨어 PoC 범위**: 프린터 1대, 110mm 롤 고정 / **플랫폼 범위**: 멀티유저(Tailscale 내부망), 1인 1기기"
- 절대금지 6 → "**사용자 레이아웃·위젯에 임의 HTML/CSS/JS를 허용하지 않는다.** 위젯 스크립트는 `haru-widget-runner` 샌드박스에서만 실행되고 **블록 JSON만 반환**한다. 서버 헤드리스 Chromium이 사용자 HTML을 여는 경로는 없어야 한다"
- 구성요소 경계에 한 줄 추가: "**사용자 스크립트를 아는 코드는 `/server/runner`(Node)뿐이다.** JVM은 번들을 실행하지 않고 러너 HTTP만 호출한다"
- docs 안내 표에 `docs/server/layout-schema.md`, `docs/server/widgets.md`, `docs/server/runner.md`, `docs/app/studio.md` 추가

## 3. 도메인 모델과 용어

```
User ──owns──▶ Device (1:1)
User ──owns──▶ Layout ──has──▶ Row ──has──▶ Slot ──refs──▶ WidgetVersion (고정 버전)
User ──owns──▶ Schedule ──▶ Layout, Device
User ──owns──▶ Widget ──has──▶ WidgetVersion (불변, semver)
User ──owns──▶ LayoutPublication (게시 시점 스냅샷, 불변)
User(작가) ──writes──▶ Post
User ──subscribes──▶ User(작가)
User ──owns──▶ Feed ──has──▶ FeedItem
Slot ──has──▶ SlotState (KV 4KB + 마지막 성공 출력)
Render ──▶ Layout × targetDate (슬롯별 결과는 renders.meta)
Command / Result ──▶ Device
UsageEvent (원장)
```

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 레이아웃 | Layout | 종이 한 장의 설계. 행 목록. (구 "포맷") |
| 행 | Row | 가로 한 줄. 슬롯 1~2개 |
| 슬롯 | Slot | 행 안의 칸. 위젯 1개 + 버전 + props + onError |
| 위젯 | Widget | 마켓에 게시되는 단위. `@handle/slug` |
| 위젯 버전 | WidgetVersion | 게시된 불변 버전. manifest + 번들 |
| 위젯 인스턴스 | (= Slot) | 레이아웃에 놓인 위젯 |
| 1st-party 위젯 | Built-in widget | `@haru/*`. Java 구현. 버전 고정 예외(항상 최신) |
| 블록 | Block | 위젯이 반환하고 렌더러가 그리는 최소 단위 |
| 작가 | Author | 글을 1개 이상 게시한 사용자 |
| 글 | Post | 작가가 쓴 Markdown 콘텐츠 |
| 구독 | Subscription | 사용자 → 작가 |
| 피드 | Feed | 사용자가 등록한 외부 RSS/Atom/JSON Feed |
| 마켓 | Market | 위젯·레이아웃·작가 카탈로그 |
| 게시 | Publish | 마켓에 올림 (버전 불변) |
| 설치 | Install | 위젯: 참조+고정 / 레이아웃: 복사 |
| 핸들 | Handle | 사용자 고유 id (`@handle`) |
| 러너 | Runner | `haru-widget-runner` 컨테이너 |
| 예약·occurrence·명령·결과·렌더·스냅샷·프린터 프로필·용지 정책 | 기존 용어 유지 (`docs/architecture.md` 용어집) |

## 4. M6 — 계정·기기 소유

### 4.1 인증

| 항목 | 값 |
|---|---|
| 라이브러리 | `spring-boot-starter-security`, `spring-session-jdbc` (세션이 재기동을 넘김) |
| 로그인 | `POST /api/auth/login {email, password}` → 200 + `Set-Cookie: SESSION` (HttpOnly, Secure, SameSite=Lax). 폼 로그인 리다이렉트 없음(SPA) |
| 비밀번호 | bcrypt (`DelegatingPasswordEncoder` 기본), 최소 10자 [기본값] |
| CSRF | `CookieCsrfTokenRepository.withHttpOnlyFalse()` + 앱이 `X-XSRF-TOKEN` 헤더 전송. `/api/device/*`는 CSRF 제외(Bearer) |
| 가입 | `POST /api/auth/signup {email, password, handle, displayName}`. 오픈 가입. 이메일·핸들 UNIQUE |
| 핸들 규칙 | `^[a-z0-9](?:[a-z0-9-]{1,18}[a-z0-9])?$` (3~20자), 예약어(`haru`, `admin`, `api`, `studio`, `market` 등) 금지, **변경 불가** |
| 관리자 | `.env` `HARU_ADMIN_EMAIL`. 그 이메일로 가입한 계정이 `admin`. 관리자 API는 `ROLE_ADMIN` |
| 비밀번호 재설정 | 메일 인프라 없음 → 관리자 화면에서 임시 비밀번호 발급 → 다음 로그인 때 변경 강제 |
| 로그인 시도 제한 | IP당 10회/분 [기본값] (Bucket4j 또는 인메모리) |
| 미인증 요청 | 401 `ProblemDetail`. 앱은 `/login`으로 |

### 4.2 리소스 소유

- `formats`(→M7에서 `layouts`), `schedules`, `assets`, `renders`, `commands`, `results`, `settings`에 **`owner_user_id`** (또는 `device_id` 경유) 추가. 모든 조회·수정은 `where owner_user_id = 현재 사용자`.
- `settings` 키-값 1벌 → `user_settings(user_id, key, value)`. 날씨 위치 등 기존 키 그대로.
- 기존 PoC 데이터: Flyway `V2__users_and_ownership.sql`이 **"부트스트랩 사용자"**를 만들지 않는다. 대신 마이그레이션은 컬럼을 NULL 허용으로 추가하고, **관리자가 가입한 뒤 `POST /api/admin/claim-legacy`** 로 owner가 NULL인 모든 행을 자기 것으로 가져온다(1회). 그 뒤 컬럼을 NOT NULL로 바꾸는 `V3`는 M7에서.

### 4.3 기기 토큰

| 항목 | 값 |
|---|---|
| 테이블 | `devices(id, owner_user_id UNIQUE, name, token_hash, token_issued_at, printer_profile JSON, last_poll_at, last_seen_ip, created_at)` |
| 토큰 | 32바이트 난수 → base64url. **한 번만 표시**. DB엔 SHA-256만. 재발급 시 이전 토큰 즉시 무효 |

| Pi 규약 | `/api/device/{poll,snapshot,renders,results}` 요청·응답 **불변**. 스냅샷은 이제 "이 기기 소유자의 예약·렌더"만 담는다 |

### 5.1 레이아웃 JSON (schemaVersion 2)

```json
{
  "schemaVersion": 2,
  "name": "아침 종이",
  "style": { "fontFamily": "Pretendard", "baseFontSizePt": 11, "lineHeight": 1.5, "marginMm": 4, "blockGapMm": 3 },
  "rows": [
    { "id": "r1", "slots": [
      { "id": "s1", "width": "1/1", "widget": "@haru/dateHeader", "version": "builtin", "props": { "pattern": "M월 D일 dddd" }, "onError": "remove" }
    ]},
    { "id": "r2", "slots": [
      { "id": "s2", "width": "2/3", "widget": "@haru/posts", "version": "builtin", "props": { "source": "all", "mode": "new", "maxPosts": 1 }, "onError": "remove" },
      { "id": "s3", "width": "1/3", "widget": "@haru/weather", "version": "builtin", "props": {}, "onError": "lastGood" }
    ]},
    { "id": "r3", "slots": [
      { "id": "s4", "width": "1/1", "widget": "@jane/habit-tracker", "version": "1.2.0", "props": { "habits": ["물", "산책"] }, "onError": "remove" }
    ]}
  ]
}
```

| 규칙 | 값 |
|---|---|
| 행 수 | 1~30 [기본값] |
| 슬롯 폭 조합 | `1/1` / `1/2+1/2` / `2/3+1/3` / `1/3+2/3` |
| 슬롯 사이 간격 | 3mm [기본값]. 행 사이는 `style.blockGapMm` |
| `version` | 1st-party는 `"builtin"`, 사용자 위젯은 정확한 semver |
| `onError` | `remove`(기본) / `lastGood`(슬롯 state의 마지막 성공 출력 재사용, 없으면 remove) |
| `id` | 레이아웃 안 고유. `slot_state`의 키 |
| 기존 `meta.author`, `forkedFrom` | `source`로 대체: `{ publicationId, version, installedAt }` (마켓 설치) 또는 `{ importedFrom: ... }`(JSON 가져오기) |
| 가져오기/내보내기 | 유지. 내보내기는 assets를 data URI로 내장(기존 규칙), 사용자 위젯 참조는 id+버전만 — 받는 쪽에 없으면 슬롯을 "설치 필요"로 표시 |

**동적 레이아웃 판정**: 슬롯 중 하나라도 `manifest.data`에 `date/printer/profile` 외 항목(`weather`, `posts`, `feed`)이 있거나 `state: true`면 동적 → 기존 규칙대로 **occurrence 약 60분 전 재렌더**. (posts/feed의 "지난 인쇄 이후 새 것" 판정이 stale해지지 않도록)

| `heading` | `text`, `level 1~3` | `align` | |
| `image` | `assetId` | `widthPct 10~100`, `align` | assetId는 props(사용자 선택)나 위젯 버전에 동봉된 에셋만 참조 가능 |

### 5.3 위젯 계약

```ts
// haru.d.ts — 에디터에 제공하는 타입
export const manifest: {
  name: string;                 // 표시 이름 (id는 서버가 @handle/slug로 부여)
  version: string;              // semver. 게시마다 증가
  description?: string;
  inputs: JSONSchemaSubset;     // 사용자 설정 폼 자동 생성
  sample: Record<string, unknown>;   // inputs를 만족하는 예시 → 미리보기·게시 검사·썸네일
  data?: Array<'date' | 'weather' | 'posts' | 'feed' | 'profile' | 'printer'>;
  state?: boolean;              // 인스턴스 KV 사용 여부
};
export function render(ctx: Ctx): Block[];

type Ctx = {
  date: { iso: string; weekday: 0|1|2|3|4|5|6; time: string; tz: 'Asia/Seoul' };
  props: Record<string, unknown>;          // inputs 검증 통과본
  data: {
    weather?: { ...기존 weather 블록 데이터 };
    posts?: Array<{ id; authorHandle; authorName; title; publishedAt; blocks: Block[] }>;   // 최신 ≤ 20
    feed?: Array<{ id; title; link; summary; publishedAt }>;                                 // 최신 ≤ 50
    profile?: { handle; displayName };
    printer: { widthMm; printableWidthPx; dpi };
  };
  state: { get(): Record<string, unknown>; set(next: Record<string, unknown>): void };   // ≤ 4KB
  util: { formatDate(iso: string, pattern: string): string; truncate(s: string, n: number): string };
};
```

| 규칙 | 값 |
|---|---|
| `inputs` 지원 타입 | `string`(+`format: textarea`), `number`(min/max), `boolean`, `enum`, `array of string`(≤ 20), 커스텀 `x-haru: author \| authors \| feed \| asset` → 폼에 선택기 |
| `posts` 주입 | props 중 `x-haru: author/authors`가 있으면 그 작가들, 없으면 **내 구독 전체**의 최신 글 |
| `feed` 주입 | props 중 `x-haru: feed` 필수. 없으면 검증 실패 |
| 결정성 | `Date.now()`·`new Date()`는 렌더 시각 고정, `Math.random`은 렌더마다 고정 시드 [기본값] |
| state 커밋 | 렌더 시 `set()`한 값은 `renders.meta.slotStates[slotId]`에 임시 저장 → `results`가 `printed`로 오면 `slot_state`에 커밋. 실패한 렌더는 상태를 못 바꾼다 |
| `lastGood` | `slot_state.last_output`(블록 JSON)도 같은 시점에 커밋 |

### 5.5 렌더 파이프라인 (변경)

```
occurrence (layoutId, targetDate)
 ├─ 슬롯별로 순차 실행:
 │    1st-party → Java WidgetRenderer.render(ctx)
 │    사용자 위젯 → 데이터 주입 → 러너 POST /run → 블록 검증(5.2)
 │    실패 → onError 처리(lastGood or remove), renders.meta.slots[slotId] = {status, error}
 ├─ 재배치: 슬롯 제거 → 짝 슬롯이 1/1로 → 빈 행 제거 → 전부 비면 대체 페이지(2절 4)
 ├─ Thymeleaf HTML (블록 트리 → HTML, 기존 이스케이프·data: 인라인 규칙)
 ├─ Playwright 스크린샷 (페이지 풀 2개, 30초, 1000mm)
 └─ 그레이스케일 PNG 저장 + renders.meta (slots, slotStates, reflow 기록)
```

| 등록 | `POST /api/feeds {url}` → 즉시 1회 fetch → 성공해야 저장. 사용자당 20개 |
| SSRF 가드 | `http`/`https`, 포트 80/443만. **DNS 해석 → 결과 IP 전부 검사**: `10/8, 172.16/12, 192.168/16, 127/8, 169.254/16, 100.64/10, 0/8, 224/4, ::1, fc00::/7, fe80::/10, IPv4-mapped` 거부 → **그 IP로 접속**(Host/SNI는 원 호스트명, 리바인딩 방지) → 리다이렉트는 수동 추적 ≤ 3회, 매번 재검사 → 본문 2MB·연결+읽기 10초 → `Content-Type`이 xml/rss/atom/json 계열이 아니면 거부 |
| 파서 | ROME(RSS/Atom) + Jackson(JSON Feed). `summary_text` = HTML 태그 제거 후 ≤ 2,000자. 원격 이미지 **가져오지 않음** |
| 갱신 | 스케줄러 60분(피드별 분산) + 렌더 직전 15분 이상 지났으면 1회. 실패 5회 연속 → `error`, 앱에 표시 |
| 공유 | **비공유**. 마켓 위젯의 props에 피드 URL을 넣을 수 없다(`x-haru: feed`는 설치자가 고름). 레이아웃 게시 스냅샷에서도 feed/author 선택값은 제거 |

`@haru/feed` props: `feed`(`x-haru: feed`), `mode new|latest`, `maxItems 1~10`, `summaryMaxChars`. state는 6.3과 같은 방식.

### 6.5 통과 조건

- [ ] A가 글을 `publish_at`=내일 07:00 이전으로 게시 → B(구독)의 내일 아침 종이에 **정확히 1회** 나오고, 모레엔 안 나온다

## 7. M9 — 위젯 에디터·마켓

### 7.1 에디터 `/studio/widgets/:id`

| 항목 | 값 |
|---|---|
| 셸 | 480px 예외. ≥1024px: 코드 \| 미리보기 \| 하단 오류·로그 패널 3분할. 폰: 읽기 전용 + "데스크톱에서 편집하세요" |
| 코드 | Monaco **자체 호스팅**(CDN 로더 금지 — tailnet 전용 환경). `haru.d.ts` 주입으로 `Ctx`·`Block` 자동완성. TS/JS 선택 |
| 번들 | 브라우저 `esbuild-wasm`(자체 호스팅 wasm) → IIFE(5.4). `import` 문 발견 시 에디터가 오류(외부 패키지 없음) |
| 저장 | `PUT /api/widgets/{id}/draft { source, language, bundle }` — 초안은 버전 아님, 덮어씀 |
| manifest | 저장 시 서버가 러너 `POST /manifest`로 추출 → JSON Schema 부분집합 검증 → 결과를 에디터 우측 "설정 폼 미리보기"로 렌더 |
| 미리보기 | 좌측 폼에 `sample` 자동 채움, 수정 가능 → `POST /api/widgets/{id}/preview-html { bundle, props }` 500ms 디바운스 → iframe. PNG 버튼 → `preview-png`. 러너 로그·오류·실행 시간·메모리 표시 |
| 에셋 | 위젯 버전에 이미지 ≤ 10장, 각 ≤ 500KB 동봉 [기본값] (`image.assetId`로 참조) |

### 7.2 게시

`POST /api/widgets/{id}/publish { version }` → 서버 검사 순서:
1. 소스 ≤ 256KB, 번들 ≤ 512KB [기본값]
2. manifest 유효, `version`이 semver이고 마지막 게시 버전보다 큼, `sample`이 `inputs`를 만족
3. 러너로 `sample` 실행: 한도 안에서 성공, 출력이 5.2 검증 통과
4. `sample`로 PNG 렌더 → 썸네일 에셋 저장
5. `widget_versions` 행 생성(**불변**: manifest·source·bundle·thumbnail·published_at). `widgets.latest_version` 갱신

통과 못 하면 422 + 어떤 검사에서 왜 실패했는지. 제작자가 위젯을 내리면(`unlisted`) 마켓에서 사라지지만 **설치된 슬롯은 계속 동작**.

### 7.3 설치·고정·업데이트

- `POST /api/widgets/{id}/install` → `widget_installs(user_id, widget_id, version, installed_at)` + `usage_events.widget_installed`. "내 위젯" 목록에 등장. 레이아웃 편집기의 위젯 선택기는 1st-party + 내 위젯.
- 슬롯 `version`은 설치 시점 최신으로 고정. `GET /api/layouts/{id}/updates` → 슬롯별 `{pinned, latest}` → 앱이 "업데이트 있음" 배지.
- 적용: `POST /api/layouts/{id}/slots/{slotId}/update { version }` → 새 `inputs`로 props 검증 → 실패 시 422 `errors[].path` → 앱이 수정 폼을 먼저 띄움 → 재시도.

### 7.4 레이아웃 게시·설치

- `POST /api/layouts/{id}/publish { name, description, tags }` → `layout_publications`(스냅샷 JSON 불변, 슬롯은 게시된 위젯 버전만 허용, **author/feed/asset 선택값 제거**, 썸네일 = 오늘 날짜 PNG).
- 설치 `POST /api/market/layouts/{pubId}/install` → 내 `layouts`에 복사 + 필요한 위젯 자동 설치(고정 버전 = 스냅샷 버전) + `source` 기록 + `usage_events.layout_installed`. 선택값이 비어 있는 슬롯은 편집기에서 "설정 필요" 표시.

### 7.5 마켓 화면·API

| 항목 | 값 |
|---|---|
| 탭 | 마켓 → 세그먼트 위젯 / 레이아웃 / 작가 |
| 카드 | 썸네일, 이름, `@handle`, 버전, 설치 수, 태그 |
| 검색·정렬 | `q`(이름·태그, LIKE), `tag`, `sort=recent\|installs` |
| API | `GET /api/market/widgets`, `/layouts`, `/authors`(글 수·구독자 수·최근 글), `GET /api/market/widgets/{id}`(버전 목록·소스 열람) |
| 신고 | `POST /api/reports { targetType widget\|layout\|post\|user, targetId, reason }` |
| 관리자 | `/admin`: 신고 목록, 위젯/레이아웃/글 **비공개 처리**, 사용자 **정지**(로그인 차단 + 게시물 비공개), 임시 비밀번호 |

### 7.6 통과 조건

- [ ] 계정 A가 에디터에서 TS로 위젯을 만들고 미리보기·게시 → 계정 B가 마켓에서 설치해 레이아웃에 넣고 **인쇄**
- [ ] A가 1.1.0을 게시 → B에 배지 → B가 적용, `inputs` 바뀐 경우 수정 폼 경유
- [ ] A가 위젯을 내려도 B의 슬롯은 계속 인쇄
- [ ] 7.2의 5단계 검사가 각각 실패 케이스를 422로 잡는다 (테스트 고정)
- [ ] B가 A의 레이아웃을 설치 → 위젯 자동 설치, feed/author 슬롯은 "설정 필요"
- [ ] 폰에서 에디터 진입 시 읽기 전용, 데스크톱에서 편집 가능 (브라우저 실사)
