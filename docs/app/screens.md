# 화면 명세 (웹앱 11개)

> 담당: 서버 세션 / 마일스톤: M3(스캐폴드) + M6(인증·계정·기기 관리) + M7 일부(위젯 그리드 편집기) / 기준: [../init_plan.md](../init_plan.md) 8.3절, `.temp/03` 4.4절
> API 경로는 [../architecture.md](../architecture.md)·[../server/auth.md](../server/auth.md) 규약 이름 그대로. 포맷 구조(v3, 위젯 그리드)는 [../server/format-schema.md](../server/format-schema.md)·[../server/widgets.md](../server/widgets.md), 편집기 구현은 [editor.md](editor.md)
> 표기: **[기본값]** = 따로 묻지 않고 정한 값 / **[확인됨·코드]** = 코드에서 확인

## 공통

- **모바일 우선**: 기준 폭 360~412px(Android `s21`). 데스크톱은 가운데 정렬된 좁은 컬럼으로 충분.
- **크롬** [기본값]: 셸 최대폭 480px, 바깥 배경 `--bg-page`(`#f4ede3`) 우드톤, 카드 `--bg-surface`. 탭 루트는 sticky `PageHeader`. 하단 탭 4개(`포맷` · `예약` · `지금 인쇄` · `더보기`)는 SVG 라인 아이콘+라벨. 포맷 편집·로그인·가입 화면은 하단 탭을 숨긴다. 목록 메뉴·삭제 확인은 하단 시트. PWA `theme_color`/`background_color`는 `#f4ede3`. 설정에서 어두운 테마·영어 UI(크롬 문구)를 고를 수 있다.
- **내비게이션** [확인됨·코드, `App.tsx`·`components/Layout.tsx`]: 인증되지 않으면 `/login`·`/signup`만 접근 가능(하단 탭 없음). 인증되면 하단 탭 4개 — `포맷`(`/`) · `예약`(`/schedules`) · `지금 인쇄`(`/print-now`) · `더보기`(`/more`). `더보기`는 탭이 아니라 **메뉴 화면**으로, 이력·기기·계정·설정 4개로 들어간다. 포맷 편집(`/formats/new`, `/formats/:id/edit`)은 포맷 목록에서 들어가는 하위 화면이라 하단 탭을 숨긴다.
- **시각 표시**: 전부 KST. 날짜 `2026-09-14 (월)`, 시각 `07:00` 형식 [기본값].
- **연결 오류 공통 처리**: `/api` 요청이 네트워크 오류로 실패하면 상단 배너 "서버에 연결할 수 없습니다. 폰의 Tailscale이 켜져 있는지 확인하세요." + 다시 시도 버튼.
- **인증 오류 공통 처리**: 세션이 없거나 만료돼 401이 오면 `RequireAuth` 게이트가 `/login`으로 돌려보낸다(가려던 경로는 `location.state.from`에 저장했다가 로그인 성공 후 복귀) [확인됨·코드]. 관리자가 임시 비밀번호를 발급한 계정은 로그인 성공 시 `/account`로 강제 이동한다(`mustChangePassword`).
- **서버 오류 응답**: 서버는 `application/problem+json`(`{type, title, status, detail, instance, errors[]}`, [../architecture.md](../architecture.md) 4.1)으로 답한다. 검증 오류(422, 일부 400)는 `errors[].path`(예: `widgets[2].props.ticker`)로 해당 입력을 찾아 `errors[].message`를 옆에 표시. 그 밖의 오류는 `detail`(없으면 `title`)을 토스트로.
- **삭제 확인**: 포맷·예약 삭제는 하단 시트로 확인한다.

## (0) 로그인

**목적**: 이메일/비밀번호로 세션을 연다. 인증되지 않은 사용자가 다른 경로로 가면 여기로 돌아온다.

**표시 요소**: 이메일·비밀번호 입력, 로그인 버튼, 가입 화면 링크.

**사용자 동작**
| 동작 | API |
|---|---|
| 로그인 | `POST /api/auth/login {email, password}` → 성공 시 원래 가려던 경로로(없으면 `/`), 단 `mustChangePassword`면 `/account` |

**오류 상태**: 401(자격 증명 불일치)은 일반 오류 문구, 422(필드 검증)는 `errors[].path`로 필드 옆 표시.

**CSRF 쿠키 선요청** [확인됨·코드, 2026-09-18]: 화면 진입 시 CSRF 쿠키(`XSRF-TOKEN`)가 없으면 `GET /api/auth/me`를 한 번 조용히 호출해 쿠키만 받아 둔다(401 응답이어도 결과는 무시). 새 브라우저에서 다른 화면을 거치지 않고 `/login`을 바로 열면 그 전에 `/api`를 부른 적이 없어 첫 로그인 `POST`가 403으로 실패하던 버그를 고쳤다(실측 2026-09-18).

## (0b) 회원가입

**목적**: 이메일·비밀번호·핸들·표시 이름으로 새 계정을 만든다. 핸들은 가입 후 변경 불가.

**표시 요소**: 이메일, 비밀번호, 핸들(`[a-z0-9]`로 시작·끝, 하이픈 허용, 클라이언트에서도 서버와 같은 정규식으로 즉시 검사), 표시 이름, 가입 버튼, 로그인 화면 링크.

**사용자 동작**
| 동작 | API |
|---|---|
| 가입 | `POST /api/auth/signup {email, password, handle, displayName}` → 성공 시 `/login`으로 이동(자동 로그인 아님) |

**오류 상태**: 422 필드 오류(이메일 중복, 핸들 중복·형식 오류 등)를 필드 옆에 표시.

**CSRF 쿠키 선요청**: 로그인 화면과 동일하게 진입 시 CSRF 쿠키를 미리 받아 둔다(위 (0) 참고) [확인됨·코드, 2026-09-18].

## (1) 포맷 목록

**목적**: 내 포맷(=카드) 라이브러리. 새로 만들기, 가져오기, 내보내기의 출발점.

**표시 요소**
- 포맷 카드 목록: 이름(`meta.name`), 동적 포맷이면 "매일 갱신" 배지(`hasDynamicBlocks`), 가져온 포맷이면 "원작자: {forkedFrom.author}" 표시, 마지막 수정 시각
- 썸네일 [기본값]: 저장된 포맷의 `GET /api/formats/{id}/preview.png` 상단 일부. 목록 로딩이 느리면 M3에서 생략 가능
- 버튼: `새 포맷`, `가져오기`
- 각 포맷 메뉴: `편집`, `예약하기`(→ 화면 3에 포맷 선택된 상태로 이동), `지금 인쇄`(→ 화면 4에 포맷 선택된 상태로 이동), `내보내기`, `삭제`

- **아침 브리핑**(추천 배지): 날짜 · 고도원의 아침편지 · 오늘의 날씨 · 미국 증시를 한 장에 → `/formats/new?template=morning`
- **빈 포맷**: 위젯을 직접 골라 담기 → `/formats/new?template=empty`

**사용자 동작**
| 동작 | API |
|---|---|
| 목록 로드 | `GET /api/formats` |
| 새 포맷 | (API 호출 없음) → 화면 2로 이동, 템플릿은 `?template=` 쿼리로 전달 |
| 가져오기 | 파일 선택(.json) 또는 JSON 붙여넣기 → `POST /api/formats/import` → 새로 생긴 포맷 편집 화면으로 |
| 내보내기 | `GET /api/formats/{id}/export` → JSON 파일 다운로드(파일명은 서버 `Content-Disposition`의 `<name>.haru-format.json`) |
| 삭제 | `DELETE /api/formats/{id}` |

**빈 상태**: "아직 포맷이 없습니다. 첫 카드를 만들어 보세요." + `새 포맷` 버튼
**오류 상태**

**레이아웃 메모**: 한 줄에 카드 1개. 메뉴는 카드 오른쪽 `⋯` 버튼 → 하단 시트.

## (2) 포맷 편집

**목적**: 안드로이드 홈 화면 위젯처럼, 미리 정해진 크기의 위젯을 4열 그리드에 순서대로 담아 카드를 만들고, 인쇄물과 똑같은 미리보기를 본다. **2026-09-18에 드래그 기반 행/슬롯 편집기를 폐기하고 이 방식으로 바꿨다** — 위젯 종류·크기·설정 폼은 서버 카탈로그(`GET /api/widgets`)로 **자동 생성**되고, 앱은 위젯 종류를 하드코딩하지 않는다. **구현 상세(컴포넌트 경계, 필드 kind별 입력기, 422 매핑)는 [editor.md](editor.md)를 본다** — 이 절은 화면 동작만 적는다.

**표시 요소**
- 상단: 포맷 이름 입력(필수), 설명 입력(접힘), **`저장` 버튼(명시적 저장)**, 저장 상태(저장됨 / 변경 사항 있음)
- **배치도**: 서버와 같은 4열 CSS 그리드(`grid-auto-flow: row dense`)로 위젯을 상자로 그린다. 상자 안: 아이콘·이름·요약(예: `AAPL · 14일`, `성남시 분당구`). 자동 높이 위젯(`4xauto`)은 그 위젯이 정한 미리보기 행 수만큼 그린다. **상자를 누르면 그 위젯 설정 시트를 연다**
- **위젯 목록**(순서 = 인쇄 순서): 카드마다 ▲▼(순서 이동) · 설정 · 삭제. **드래그 없음**
- **＋ 위젯 추가** → 바텀시트 카탈로그(카탈로그에 노출되는 위젯만): 아이콘·이름·설명·크기 칩. 누르면 기본 크기·기본 설정값으로 추가하고, 필수값이 비어 있으면(예: `weather`의 위치) 바로 그 위젯의 설정 시트가 열린다
- **설정 시트**: 크기 선택(세그먼트/카드) + 그 위젯의 설정 스키마로 **자동 생성한 폼**(문자열/여러 줄 텍스트/정수/켜기끄기/선택/위치 선택기 — [editor.md](editor.md) 6절). 이전 버전에서 만든, 이 앱이 편집할 수 없는 위젯은 "이전 버전 위젯" 카드로 보여 주고 삭제·순서 이동만 허용한다
- **미리보기**: 서버 실제 렌더 — 1초 디바운스, 위젯이 0개거나 필수값이 빈 위젯이 있으면 호출하지 않고 안내문. 화면에 항상 보이는 섹션(접기 가능)

**사용자 동작**
| 동작 | API |
|---|---|
| 편집 화면 진입 | `GET /api/formats/{id}`(기존) 또는 템플릿 조립(신규, API 호출 없음) |
| 위젯 카탈로그 조회 | `GET /api/widgets` |
| 위치 선택기 목록 | `GET /api/widgets/locations`(설정 시트에서 `weather` 위젯을 열었을 때) |
| 위젯 추가·순서·크기·설정값 변경·삭제 | 로컬 상태 변경(API 호출 없음) |
| 저장 | `저장` 버튼 → 신규면 `POST /api/formats`, 기존이면 `PUT /api/formats/{id}` |
| 미리보기 요청 | 자동(1초 디바운스) → `POST /api/formats/preview` |
| 저장 후 예약하기 / 지금 인쇄 | `/schedules?formatId=<id>` / `/print-now?formatId=<id>`로 이동(둘 다 API 호출 없이 이동만) |

**빈 상태**: 위젯이 0개면 "아직 위젯이 없습니다. 아래에서 위젯을 추가하세요."
**오류 상태**
- 저장 실패(검증 오류 422): `errors[].path`(`widgets[i].props.<key>`)로 해당 위젯 카드·설정 시트에 메시지
- 미리보기 검증 오류(422): 같은 방식으로 위젯별 메시지, 위젯 0개/필수값 누락이면 애초에 요청하지 않는다
- 미리보기 렌더 실패: 미리보기 자리에 오류 메시지
- 편집 중 이탈: 저장 안 된 변경이 있으면 확인 대화상자

**레이아웃 메모**: 배치도·목록·추가 버튼·미리보기 모두 셸 480px 안에서 세로로 쌓인다(캔버스+팔레트라는 옛 2단 구조 없음). 미리보기 PNG는 **폭 100%로 축소 표시**한다.

## (3) 예약 목록·편집

**목적**: 반복/일회성 예약을 만들고, 켜고 끈다. 예약 1개 = 포맷 1개(Q9).

**표시 요소**
- 예약 목록: 포맷 썸네일(`GET /api/formats/{id}/preview.png`) [확인됨·코드, 2026-09-18 추가], 시각(`07:00`), 요일(반복: `월 화 수 목 금`) 또는 날짜(일회성: `2026-09-15 (화)`), 포맷 이름, **켜기/끄기 스위치**
- 다음 실행 예정 시각 [기본값]: 앱이 KST 기준으로 계산해 표시(표시용일 뿐, 실제 실행 판단은 Pi)
- `새 예약` 버튼

**포맷 목록에서 들어오면 자동으로 시트가 열린다** [확인됨·코드, 2026-09-18]: `?formatId=<id>`로 이 화면에 들어오면(포맷 목록·편집 화면의 "예약하기" 버튼) 그 포맷이 선택된 채로 새 예약 시트가 자동으로 열린다. 쿼리는 열고 나서 바로 지운다(뒤로 가기·새로고침 때 다시 열리지 않게). 포맷 목록이 아직 새로고침 전이라 그 포맷이 안 보이면(방금 새로 만든 포맷 등) 목록이 다시 로드될 때까지 기다렸다가 연다.

**편집 시트**
- 종류: `반복` / `일회성`
- 반복: **빠른 선택 칩**(`매일`/`평일`/`주말`) [확인됨·코드, 2026-09-18 추가] + 요일 선택(월~일 토글, 최소 1개). **새 예약의 요일 기본값은 매일(7일 전부)**로 바뀌었다(이전엔 빈 선택)
- 시각(기본값 `07:00`)
- 일회성: 날짜, 시각(과거 날짜·시각은 선택 불가 [기본값])
- 포맷 선택(목록에서 1개, `?formatId=`로 들어왔으면 미리 선택돼 있다)
- 켜짐 여부
- 시간대 선택 UI 없음(KST 고정)

**사용자 동작**
| 동작 | API |
|---|---|
| 목록 로드 | `GET /api/schedules` (+ 포맷 이름 표시용 `GET /api/formats`) |
| 새 예약 | `POST /api/schedules` |
| 편집 저장 / 켜기·끄기 스위치 | `PUT /api/schedules/{id}` |
| 삭제 | `DELETE /api/schedules/{id}` |

**빈 상태**
- 예약 0개: "예약이 없습니다. 매일 아침 받을 카드를 예약하세요." + `새 예약`
- 포맷 0개인데 새 예약: "먼저 포맷을 만드세요" + 포맷 목록으로 이동 버튼

**오류 상태**
- 요일 미선택·포맷 미선택: 저장 버튼 비활성
- 스위치 변경 실패: 스위치를 원래 상태로 되돌리고 토스트

**안내 문구**(목록 하단 작은 글씨) [기본값]
- "Pi는 약 30초마다 서버에서 예약을 받아옵니다. 변경 직후 바로 반영되지 않을 수 있습니다."
- "예약 시각에 인터넷이 끊겨도 Pi가 마지막으로 받은 카드로 인쇄합니다. 이 경우 날짜·날씨는 마지막 렌더 값일 수 있습니다."

## (4) 지금 인쇄

**목적**: 선택한 포맷을 즉시 인쇄하는 명령을 보낸다.

**표시 요소**
- 포맷 선택(목록 또는 화면 1에서 넘어온 값) + 선택한 포맷 미리보기 PNG
- 기기 상태 요약: Pi 마지막 폴링 시각, 용지 정책
- **체크박스: "프린터 앞에서 용지를 눈으로 확인함"**
- `지금 인쇄` 버튼

**용지 정책별 동작** (정책 값은 `GET /api/device` 응답, 정의는 init_plan 8.1)
| 정책 | 의미 | 화면 동작 |
|---|---|---|
| `unverified` (기본, H4 통과 전) | 프린터 용지 감지가 아직 확인되지 않음. 예약 인쇄는 `dry_run` 기록만 하고, 지금 인쇄만 사람 확인 후 전송 | **체크박스를 체크해야 버튼 활성화**. 체크 없으면 버튼 비활성 + 설명 "용지 감지가 아직 확인되지 않아, 용지를 직접 확인해야 인쇄할 수 있습니다" |
| `status_query` (H4 통과 후) | Pi가 인쇄 직전 프린터에 상태를 물어 용지 확인 | 체크박스는 표시하되 필수 아님 [기본값] |
| `manual_flag` (H4 실패 시) | 서버의 수동 "용지 장착됨" 상태가 켜져 있을 때만 무인 인쇄 | 체크박스 체크 필수 [기본값]. 수동 상태가 꺼져 있으면 "기기 화면에서 용지 장착됨을 켜세요" 안내 링크 |

**사용자 동작**
| 동작 | API |
|---|---|
| 기기 상태·정책 로드 | `GET /api/device` |
| 포맷 목록·미리보기 | `GET /api/formats`, `GET /api/formats/{id}/preview.png` |
| 인쇄 | `POST /api/print-now` `{formatId, paperConfirmed}` |

**전송 후**: "명령을 보냈습니다. Pi가 다음 폴링(최대 약 30초)에 받아 인쇄합니다." + `이력 보기` 버튼. 결과는 이력 화면(5)에서 확인.

**빈 상태**: 포맷 0개 → "먼저 포맷을 만드세요"
**오류 상태**
- Pi 마지막 폴링이 오래됨 [기본값: 2분 이상]: 경고 배너 "Pi가 최근에 접속하지 않았습니다. 명령은 10분 안에 Pi가 다시 접속하면 처리되고, 그렇지 않으면 만료되어 인쇄되지 않습니다." (전송은 허용)
- 서버는 `paperConfirmed=false`여도 거절하지 않는다(판단은 Pi 용지 정책). 그래서 체크 요구는 **앱 UI에서** 한다(위 정책별 동작 표)

## (5) 이력

**목적**: 예약 실행·지금 인쇄 결과를 확인한다. Pi가 오프라인이었다면 복구 후 한꺼번에 올라온다.

**표시 요소**
- 결과 목록(최신순): 상태 라벨(색), 포맷 이름, 예약 시각(`scheduledAt`) / 실행 시각(`executedAt`), 구분(`source`: `schedule` = 예약 / `command` = 지금 인쇄), `detail`(있으면 펼쳐 보기)
- 필터 [기본값]: 전체 / 인쇄됨 / 문제 있음(printed·dry_run 외)

**상태 라벨** (`status` 7종, init_plan 6.5)
| status | 한국어 라벨 | 의미 | 색 [기본값] |
|---|---|---|---|
| `printed` | 인쇄됨 | 프린터로 전송 완료 | 초록 |
| `dry_run` | 모의 실행 | 용지 감지 미확정(`unverified`)이라 인쇄하지 않고 기록만 | 회색 |
| `missed` | 놓침 | 유예 시간(30분) 안에 실행하지 못함 | 주황 |
| `failed` | 실패 | 실행 중 오류(detail 참고) | 빨강 |
| `skipped_no_paper` | 용지 없음 | 용지가 없거나 수동 "용지 장착됨"이 꺼져 있어 건너뜀 | 주황 |
| `skipped_clock_unsynced` | 시각 미확인 | Pi 시계가 동기화되지 않아(오프라인 재부팅) 보류 | 주황 |
| `skipped_printer_offline` | 프린터 응답 없음 | 프린터 꺼짐·연결 끊김 | 빨강 |

**사용자 동작**
| 동작 | API |
|---|---|
| 목록 로드·새로고침 | `GET /api/history` (당겨서 새로고침 [기본값]) |

**빈 상태**: "아직 실행 기록이 없습니다."
**오류 상태**: 로드 실패 시 공통 연결 오류 배너

## (6) 기기

**목적**: Pi·프린터가 살아 있는지, 어떤 용지 정책으로 동작하는지 보고, 수동 용지 상태를 조작한다.

**표시 요소**
- **Pi 마지막 폴링 시각** + 경과 시간("35초 전"). 기준 초과 시 경고 [기본값: 2분]
- **프린터 프로필**: `model`(표시용, 예 `m832`), `dpi`, `paperWidthMm`, `printableWidthPx`
- **프린터 상태**: Pi가 보고한 `printerStatus` `{state, detail}`(정의는 [../architecture.md](../architecture.md) 4.3). `detail`이 있으면 라벨 아래 작은 글씨로 표시

  | `state` | 한국어 라벨 | 색 [기본값] |
  |---|---|---|
  | `ok` | 정상 | 초록 |
  | `offline` | 프린터 연결 안 됨 | 빨강 |
  | `error` | 오류 | 빨강 |
  | `unknown` | 알 수 없음 | 회색 |

  H4(용지 감지) 통과 후 `no_paper`(용지 없음), `cover_open`(커버 열림)이 추가될 예정이다. 모르는 값은 `unknown`처럼 표시한다
- **용지 정책**: `unverified` / `status_query` / `manual_flag` + 한 줄 설명(화면 4의 표와 같은 문구)
- **수동 "용지 장착됨" 토글**
- **(M6 추가) 기기 토큰 발급**: 버튼을 누르면 **확인 절차 없이 바로** 평문 토큰이 발급돼 **한 번만** 화면에 표시된다(재조회 불가) [확인됨·코드, `DevicePage.tsx`]. "복사" 버튼(클립보드), 복사 완료 시 2초간 표시 바뀜. 표시 아래에 경고 문구(`tokenWarning`: "이 토큰은 다시 볼 수 없습니다. Pi의 .env 파일의 HARU_DEVICE_TOKEN에 붙여넣고 재시작하세요.")가 뜬다. `pi/.env`의 `HARU_DEVICE_TOKEN`에 붙여넣으라는 안내.
- **(M6 추가) 페어링 코드 발급**: 버튼을 누르면 **확인 절차 없이 바로** 코드와 만료 시각이 표시되고, **초 단위 만료 카운트다운**이 돈다 [확인됨·코드]. 발급 후 안내 배너(`pairingCodeWarning`: "Pi에서 haru-agent pair 명령을 지원하기 전에는 위의 토큰 발급을 사용하세요.")가 뜬다 — **즉 페어링 코드 기능은 Pi 쪽 `pair` 명령이 아직 없어 현재 실사용 경로가 아니고, UI 자체가 토큰 발급 쪽을 쓰라고 안내한다**[확인됨·코드, `i18n/ko.ts` `pairingCodeWarning`]. `pair` 절차 자체의 구현 시점은 `.temp/03` M6.
- **(M6 추가) 내 기기 정보**: 기기 이름, 연결(페어링) 여부(`GET /api/devices/me`).

**수동 "용지 장착됨" 토글의 의미**
- `manual_flag` 정책일 때만 실제로 쓰인다: 켜져 있어야 Pi가 무인(예약) 인쇄를 한다. 롤을 갈았을 때 사용자가 켠다. 프린터가 오류를 보고하면 서버가 자동으로 끈다.
- 다른 정책에서는 토글을 비활성(회색)으로 두고 "현재 정책에서는 사용하지 않습니다" 표시 [기본값].

**사용자 동작**
| 동작 | API |
|---|---|
| 상태 로드 | `GET /api/device` (화면에 있는 동안 30초마다 재조회 [기본값]) |
| 용지 장착됨 토글 | `PUT /api/device/paper-state` `{loaded}` |
| 기기 토큰 발급 | `POST /api/devices/me/token` → `{deviceId, token, issuedAt}` |
| 페어링 코드 발급 | `POST /api/devices/pairing-codes` → `{code, expiresAt}` |
| 내 기기 조회 | `GET /api/devices/me` → `{deviceId, name, paired}`(페어링 전에는 `deviceId`·`name` 키가 응답에서 아예 빠진다 — 서버 `@JsonInclude(NON_NULL)`, 앱 타입 `MyDeviceResponse`는 `deviceId: string \| null`·`name: string \| null`로 받는다) |

**참고**: `architecture.md` 4.2절은 `GET/PATCH /api/devices/me`(기기 이름 변경 가능)를 규약으로 정의하지만, 앱은 **PATCH를 호출하지 않는다** — `devicesApi`(`api/devices.ts`)에 `getMe`만 있고 기기 이름을 바꾸는 UI가 없다. 규약과 다르게 정의한 것은 아니고 규약의 일부를 아직 안 쓰는 상태다(architecture.md 원본은 그대로 둔다).

**빈 상태**: Pi가 한 번도 폴링하지 않음 → "아직 Pi가 연결되지 않았습니다." (프로필·상태 칸 비움)
**오류 상태**: 토글 실패 시 원래 상태로 되돌리고 토스트. 토큰·페어링 코드는 **버튼을 누르면 확인 절차 없이 바로 재발급되며 이전 값을 즉시 무효화**한다 — 발급 전 확인 다이얼로그는 **코드에 없다**[확인됨·코드, 2026-09-17 재확인. 발급 후 경고 배너만 있다, 위 참고]. 정책 값이 아직 없으면(Pi가 poll을 한 번도 안 함) 용지 정책 칸은 `정책 없음`으로 표시된다(`getPolicyDescription`의 기본 분기) [확인됨·코드].

## (7) 설정

**목적**: 테마·언어 같은 앱 전역 설정. **2026-09-18부터 날씨 위치는 이 화면에 없다** — 위치는 포맷의 날씨 위젯 설정에서 정한다([editor.md](editor.md) 6절, [../server/weather.md](../server/weather.md) 2절). 이 화면이 다루는 항목은 전부 이 기기 `localStorage`에만 저장된다.

**표시 요소** (카드 4개, `SettingsPage.tsx`) [확인됨·코드]
- **표시** 카드: 테마 선택(`라이트`/`어두운`/`기기 설정` — `localStorage` `haru-theme`, `lib/theme.ts`), 언어 선택(`한국어`/`English` — `useI18n()`의 `locale`). 둘 다 서버에 저장하지 않고 즉시 적용된다.
- **사용 기록** 카드: 이 기기 `localStorage`(`haru-events`, 최대 100개 보관)에 쌓인 이벤트(`format_create`/`schedule_save`/`print_now`) 중 최근 8개를 최신순으로 이름·시각(`HH:mm:ss`)으로 나열. "삭제" 버튼으로 전부 지움(`clearEvents`). 0개면 안내 문구만.
- **안내** 카드 [확인됨·코드, 2026-09-18]: "날씨 위치는 포맷의 날씨 위젯에서 정합니다." 한 줄만 표시 — 옛 "날씨 기본 위치" 입력 카드(위도·경도·위치 이름)는 지워졌다. 서버 `GET/PUT /api/settings`는 그대로 있지만 이 화면은 더 이상 호출하지 않는다(레거시, [../server/api.md](../server/api.md) "설정" 절).
- **앱 정보** 카드: 버전(`0.1.0`, 코드에 하드코딩 [확인됨·코드]), 서버 연결 상태 배지(`GET /api/health`, 연결됨/연결 안 됨/확인 중)

**사용자 동작**
| 동작 | API |
|---|---|
| 연결 확인 | `GET /api/health` |
| 테마·언어 변경 | 없음(`localStorage`만) |
| 사용 기록 삭제 | 없음(`localStorage`만) |

**빈 상태**: 사용 기록 0개면 "기록 없음" 류 안내 문구.
**오류 상태**: 서버 연결 확인 실패 시 배지가 "연결 안 됨"으로 표시(재시도 1회).

## (9) 계정

**목적**: 표시 이름·소개를 수정하고 비밀번호를 바꾼다. 로그아웃도 여기서 한다.

**표시 요소**
- 표시 이름, 소개(`bio`) 입력 — `GET /api/auth/me`로 불러와 채운다
- 비밀번호 변경 섹션: 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인
- 로그아웃 버튼
- (읽기 전용) 이메일, 핸들(`@handle`, 가입 후 변경 불가)

**사용자 동작**
| 동작 | API |
|---|---|
| 내 정보 로드 | `GET /api/auth/me` |
| 표시 이름·소개·비밀번호 저장 | `PATCH /api/account {displayName?, bio?, currentPassword?, newPassword?}` |
| 로그아웃 | `POST /api/auth/logout` → `/login`으로 이동 |

**오류 상태**: 422 필드 오류(현재 비밀번호 불일치, 새 비밀번호 규칙 위반 등)를 필드 옆에 표시. 저장 성공 시 비밀번호 입력칸은 비운다.

**참고**: 관리자가 임시 비밀번호를 발급한 계정은 로그인 직후 이 화면으로 강제 이동한다(공통절 "인증 오류 공통 처리").
